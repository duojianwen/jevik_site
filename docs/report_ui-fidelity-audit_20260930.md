## 一、结论摘要

当前个人网站**不是严格按 `example/Image` 设计图复刻的版本**。

它仍保留了参考设计的主要视觉系统：暖米色底、橙蓝渐变、玻璃拟态卡片、3D 图片素材、三栏项目卡片及整体页面结构；但当前源码已在 v2 基准之上加入中文默认文案、双分段语言切换器、非粘性导航和额外交互动画。因此，它应被定义为“基于 v2 设计的本地化改版”，而不是“像素级一致的复刻”。

### 审计结论表

| 维度 | 结论 | 说明 |
|---|---|---|
| 主要视觉资产 | 基本一致 | 字体和核心 3D/缩略图资产与 `example/jevik-site-v2` 的对应文件哈希一致。 |
| 页面结构 | 大体一致 | 8 个页面均保留基准页面的主体结构和组件体系。 |
| 文案与排版 | 不一致 | 当前默认中文，参考图为英文；字体度量、断行、卡片内容高度会随之变化。 |
| 顶部导航 | 不一致 | 当前导航为静态定位；v2 基准为粘性导航。 |
| 交互效果 | 不一致 | 当前新增双分段语言开关、按钮按压缩放及涟漪动画。 |
| 严格设计图验收 | 不通过 | 不能对当前版本作“严格按照参考图实现”或“像素级复刻”的声明。 |

## 三、参考设计的关键特征

以首页 `example/Image/home.webp` 为例，参考设计具有以下明确特征：

- 顶部为圆角玻璃导航，显示品牌、`About / Projects / Articles / Contact` 与 `Hire Me`。
- 首页首屏使用英文标题 `Jevik` 和英文角色描述。
- Hero 区左文右图，右侧使用高密度镀铬/玻璃质感 3D 视觉素材。
- 项目与文章区域采用规则三栏卡片布局。
- 整体字体、间距、留白和阅读密度围绕英文文本设计。

这些特征是本次“严格还原”判定的视觉基线。

## 四、问题清单

### P0：默认中文化改变了设计图的文字排版

**现象**

当前 8 个页面均从 `<html lang="en">` 改为 `<html lang="zh">`，默认内容由英文替换为中文；语言偏好默认值也从英文改为中文。

**证据**

- 当前首页的语言设定与语言开关：[index.html](../index.html#L2)、[index.html](../index.html#L22)。
- 当前 i18n 默认语言与切换逻辑：[assets/js/i18n.js](../assets/js/i18n.js#L166)。
- 设计图 `home.webp` 中的导航、标题、按钮及卡片均为英文。

**影响**

中文与英文的字符宽度、单词分隔规则和断行行为不同。即使栅格 CSS 不变，中文标题、介绍文案、卡片正文也可能出现不同的行数和内容高度，进而偏离设计图的垂直节奏。

**建议**

若验收目标是严格复刻，恢复英文默认语言，中文仅由用户手动切换启用。若产品目标是中文个人站，则应将中文状态重新截图并定义为新的正式设计稿，而不是继续以英文图作像素级验收依据。

### P0：导航从粘性定位改为静态定位

**现象**

当前 `.nav` 使用 `position: static`；v2 基准使用 `position: sticky; top: 14px; z-index: 50`。

**证据**

- 当前实现：[assets/css/main.css](../assets/css/main.css#L91)。
- v2 基准：`example/jevik-site-v2/assets/css/main.css` 的导航定义。

**影响**

首屏截图可能看不出差异，但当用户向下浏览项目、文章或详情页时，导航不会固定在视区顶部。这改变了基准站点的核心浏览行为，也降低长页面返回主导航的效率。

**建议**

恢复基准规则：

```css
.nav {
  position: sticky;
  top: 14px;
  z-index: 50;
}
```

### P1：新增双分段语言切换器，改变了导航的视觉节奏

**现象**

参考图顶部没有语言控件；当前每一页都新增“中 / EN”双分段开关，并通过深色滑块标识当前语言。

**证据**

- 首页开关结构：[index.html](../index.html#L22)。
- 开关样式：[assets/css/main.css](../assets/css/main.css#L145)。
- 开关状态同步：[assets/js/i18n.js](../assets/js/i18n.js#L184)。

**影响**

该控件占用导航横向空间，并在视觉上引入与参考图不一致的新焦点。它不是缺失修复，而是一次明确的二次设计。

**建议**

二选一：

1. **严格复刻路线**：移除桌面导航中的开关，恢复设计图中的简洁导航结构。
2. **中文化改版路线**：保留语言能力，但将切换器移入汉堡菜单或使用更低权重的入口，避免与主 CTA 竞争注意力。

### P1：移动端未处理新增语言开关的基准隐藏策略

**现象**

v2 基准在 `max-width: 640px` 时隐藏导航按钮及原语言按钮；当前仅隐藏了 `.nav .btn`，新增的 `.lang-switch` 不在隐藏范围内。

**证据**

- 当前移动端规则：[assets/css/main.css](../assets/css/main.css#L419)。
- 当前语言开关：[assets/css/main.css](../assets/css/main.css#L145)。

**影响**

窄屏顶部导航会比基准多出一个常驻控件，增加空间挤压与换行风险。是否已经产生溢出需要在 640px、375px 等实际视口中截图验证。

**建议**

将语言开关纳入移动菜单，或在 `max-width: 640px` 直接隐藏：

```css
@media (max-width: 640px) {
  .nav .lang-switch {
    display: none;
  }
}
```

### P2：新增按压缩放和涟漪动画，不属于参考图定义的效果

**现象**

当前样式增加了按钮、卡片与导航项按下时的 `scale(.96)` 效果；脚本还会为按钮动态创建涟漪元素。

**证据**

- 按压与涟漪样式：[assets/css/main.css](../assets/css/main.css#L435)。
- 涟漪创建逻辑：[assets/js/main.js](../assets/js/main.js#L62)。

**影响**

该效果通常不会改变静态首屏布局，但会改变交互过程中的感知，与参考图无法建立一一对应关系。

**建议**

若目标是严格还原，移除这些额外动态；若目标是体验增强，则保留，但在验收口径中改为“在 v2 风格上增强”，而非“忠实复刻”。

### P2：模板化履历和联系方式不宜直接作为个人站正式信息

**现象**

当前内容中仍包含模板化个人资料、地点、邮箱、项目成果和职业经历描述。

**影响**

这不属于 UI 一致性问题，但会直接影响个人网站的信息可信度。未被本人确认的数字、公司、奖项、用户量或 GitHub Star 数量，不应以真实履历形式上线。

**建议**

在视觉验收完成后单独开展内容替换：用可确认的真实项目、技能、联系方式和个人介绍替代模板数据。暂时无法确认的内容，应使用通用能力描述，而不是具体事实性数字。

### P3：缺少上线后的基础搜索与分享资产

**现象**

当前项目未见 `robots.txt`、`sitemap.xml` 和 Open Graph 分享图等基础资产。

**影响**

不会影响设计稿还原，但会降低搜索引擎收录质量和社交平台分享卡片的完整度。

**建议**

视觉一致性验收完成后，以独立任务补充 SEO 与分享元信息，避免和本轮视觉修复混合，影响验收范围。

## 五、当前一致部分

下列部分在本次源码检查中保持与 v2 基准一致，仍可继续复用：

- 自托管字体资源及字体体系。
- `hero-3d.png`、项目缩略图等核心视觉素材。
- 暖米色背景、橙蓝渐变、玻璃拟态卡片和镀铬质感的基础设计语言。
- 首页 Hero、项目、文章、联系区，以及各内页的主体信息架构。
- 响应式栅格主体结构。

因此，当前不需要推倒重做；主要需要收敛“基准设计”与“二次改版”之间的目标冲突。

## 六、优化路线建议

### 路线 A：严格按设计图复刻（推荐用于视觉验收）

**目标**：让当前实现回到可与 `example/Image` 和 `example/jevik-site-v2` 直接比较的状态。

1. 默认恢复英文。
2. 恢复粘性导航。
3. 移除或隐藏桌面端双分段语言切换器。
4. 恢复基准移动端语言控件策略。
5. 移除涟漪、按压缩放等基准外动画。
6. 使用统一浏览器、统一缩放比例，在 1440px、1024px、768px、640px、375px 五档视口截图。
7. 将截图与设计图进行逐页叠图或并排比对，修正可见差异后再验收。

**优点**：验收标准清晰；能够回答“是否严格按照图片实现”。

**代价**：中文化与交互增强需要推迟到设计复刻验收通过之后。

### 路线 B：保留中文化与交互增强，形成新设计版本

**目标**：把当前版本定位为适合中文用户的个人站，而不是继续追求与英文图一模一样。

1. 保留中文默认、双语能力和交互增强。
2. 为中文状态设计并确认新的桌面和移动端页面截图。
3. 重审导航在 1020px、640px、375px 下的密度与语言开关位置。
4. 补充真实个人资料、项目和联系信息。
5. 以新截图而非 `example/Image` 作为后续 UI 验收基准。

**优点**：更符合中文个人站的实际使用场景。

**代价**：不能再对外宣称与现有英文设计图严格一致。

## 七、建议的下一步

建议先由杰维克 Jevik 确认以下决策：

确认后再执行对应路线。若选择路线 A，应先完成视觉复刻和多视口截图验收，再开始内容本地化；若选择路线 B，应先产出新的中文设计稿，避免实现和验收目标继续脱节。
